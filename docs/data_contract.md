# Контракт данных

Версия 1.0, съёмка спереди (фронтальная камера). Что модуль точек (Android, iOS) передаёт модулю отжиманий (общий код KMP) и что модуль отжиманий отдаёт экрану. Меняется только новой версией с сообщением всей команде: добавили поле, значит 1.1; убрали поле или поменяли его смысл, значит 2.0.

## Модули

| Модуль | Где | Пишет | Вход | Выход |
| --- | --- | --- | --- | --- |
| Модуль точек | Android: `androidMain` на Kotlin. iOS: класс на Swift, реализует `PoseSource` | мобильщики | кадр камеры | `PoseFrame` |
| Модуль отжиманий | `commonMain`, один на обе платформы. Эталон: `pushup_logic.py` | логику и параметры подбирают на Python ML-инженер и аналитик, на Kotlin переносят мобильщики | `PoseFrame` | `PushupState` |
| Экран тренировки | Compose Multiplatform | мобильщики и дизайнер | `PushupState` | счётчик и подсказки |

## PoseFrame

Один `PoseFrame` на каждый кадр, который обработала модель.

| Поле | Тип | Значение |
| --- | --- | --- |
| `timestampMs` | Long | время кадра в миллисекундах, строго растёт |
| `imageWidth`, `imageHeight` | Int | размер кадра в пикселях, в котором человек стоит головой вверх |
| `landmarks` | List\<Landmark> или null | 12 точек в порядке таблицы ниже; null, если человек не найден |
| `Landmark.x`, `Landmark.y` | Float | доля ширины и высоты кадра; начало в левом верхнем углу, y растёт вниз; за краем кадра меньше 0 или больше 1 |
| `Landmark.z` | Float | глубина от MediaPipe, пока не используется |
| `Landmark.visibility` | Float | насколько точка видна, от 0 до 1; если платформа не отдала, 0 |
| `Landmark.presence` | Float | насколько точка в кадре, от 0 до 1; если платформа не отдала, 0 |

## Правила для модуля точек

- **Модель.** MediaPipe Pose Landmarker, файл `pose_landmarker_full.task` внутри приложения (запасной `pose_landmarker_lite.task`). Режим LIVE\_STREAM, `numPoses = 1`, остальные пороги по умолчанию (0,5).
- **Поворот.** Точки даём для кадра, где человек стоит головой вверх. Это не обязательно портретный кадр: в альбомной ориентации ширина больше высоты. Если в модель ушёл неповёрнутый кадр, точки поворачиваем перед отправкой, а при повороте на 90 или 270 градусов меняем местами `imageWidth` и `imageHeight`.
- **Зеркало.** В модель идёт незеркальный кадр, в `PoseFrame` ничего не зеркалим. При рисовании точек поверх зеркального превью фронтальной камеры x заменяем на 1 − x.
- **Время.** `timestampMs` из времени кадра камеры, строго растёт.
- **Пропущенные кадры.** Кадры, которые модель пропустила, пока была занята, не отправляем.
- **Нет человека.** Отправляем `PoseFrame` с `landmarks = null`.
- **Без обработки.** Значения MediaPipe как есть: без сглаживания и без отсева по `visibility`. Очистка в модуле отжиманий.
- **Порядок.** Результаты MediaPipe приходят в другом потоке. В модуль отжиманий передаём их по одному, по возрастанию `timestampMs`.

## Код контракта на Kotlin

Лежит в `commonMain`, проверен компилятором Kotlin 2.2. На iOS класс на Swift реализует `PoseSource` и вызывает `listener.onFrame(frame:)` на каждый результат MediaPipe.

```kotlin
// commonMain: общий код KMP. Контракт версии 1.0
package app.pushups.contract

/** Одна точка тела. */
data class Landmark(
    val x: Float,          // доля ширины кадра, 0..1
    val y: Float,          // доля высоты кадра, 0..1, ось направлена вниз
    val z: Float,          // глубина от MediaPipe, пока не используем
    val visibility: Float, // насколько точка видна, 0..1
    val presence: Float,   // насколько точка в кадре, 0..1
)

/** Наши 12 точек. Порядок фиксирован и совпадает с колонками CSV. */
enum class BodyPoint(val mediaPipeIndex: Int) {
    LEFT_SHOULDER(11), RIGHT_SHOULDER(12),
    LEFT_ELBOW(13), RIGHT_ELBOW(14),
    LEFT_WRIST(15), RIGHT_WRIST(16),
    LEFT_HIP(23), RIGHT_HIP(24),
    LEFT_KNEE(25), RIGHT_KNEE(26),
    LEFT_ANKLE(27), RIGHT_ANKLE(28),
}

/** Кадр от модуля точек. */
data class PoseFrame(
    val timestampMs: Long,          // время кадра, строго растёт
    val imageWidth: Int,            // размер кадра, где человек головой вверх
    val imageHeight: Int,
    val landmarks: List<Landmark>?, // 12 точек в порядке BodyPoint или null
)

/** Получатель кадров от модуля точек. */
fun interface PoseListener {
    fun onFrame(frame: PoseFrame)
}

/** Модуль точек: своя реализация на Android (Kotlin) и на iOS (Swift). */
interface PoseSource {
    fun start(listener: PoseListener)
    fun stop()
}

enum class Phase { UP, DOWN }

/** Подсказки по важности: показываем первую подходящую. */
enum class Hint { NO_PERSON, ARMS_HIDDEN, TOO_FAR, TOO_CLOSE }

/** Ошибки техники. Список согласуем с аналитиком после экспериментов. */
enum class TechniqueError { SHALLOW_REP }

/** Что модуль отжиманий отдаёт экрану после каждого кадра. */
data class PushupState(
    val reps: Int,
    val phase: Phase,
    val hint: Hint?,                 // null, если с кадром всё хорошо
    val errors: Set<TechniqueError>, // ошибки текущего повтора
)

/** Итог тренировки для экрана результатов. */
data class WorkoutSummary(
    val reps: Int,
    val durationMs: Long,
    val errorCounts: Map<TechniqueError, Int>,
)

/** Модуль отжиманий: общий код, один на обе платформы. */
interface PushupAnalyzer {
    fun onFrame(frame: PoseFrame): PushupState
    fun finish(): WorkoutSummary
}
```

## Что возвращает модуль отжиманий

- `onFrame` вызываем на каждый `PoseFrame` по порядку, он сразу возвращает `PushupState`.
- `reps` только растёт. Повтор засчитывается при смене `phase` с `DOWN` на `UP`, если внизу сглаженный сигнал опускался ниже порога «внизу» от текущего «верха» (как в `pushup_logic.py`).
- `hint`: не больше одной подсказки на кадр, первая подходящая по порядку `Hint`. Текст выбирает экран, в прототипе: «Встаньте в кадр», «Не видно плеч или рук», «Слишком далеко от камеры», «Слишком близко к камере».
- `errors` пока всегда пустой.
- `finish()` вызываем в конце тренировки.
- Параметры счётчика (пороги, окна) живут внутри модуля отжиманий. Код платформ их не задаёт.

## CSV для сверки телефона и компьютера

Строка CSV это один `PoseFrame`. 66 колонок: 6 служебных и по 5 на каждую из 12 точек в порядке таблицы выше.

```csv
video,frame,time_ms,width,height,detected,left_shoulder_x,left_shoulder_y,left_shoulder_z,left_shoulder_vis,left_shoulder_pres,…,right_ankle_pres
```

| Колонка | Поле `PoseFrame` | Формат |
| --- | --- | --- |
| `video` | нет, имя записи | текст без запятых, одинаковый во всех строках; файл называется `<video>.csv` |
| `frame` | нет, номер кадра камеры | целое, с 0; пропущенные моделью кадры дают разрывы в номерах |
| `time_ms` | `timestampMs` | целое, строго растёт |
| `width`, `height` | `imageWidth`, `imageHeight` | целые |
| `detected` | `landmarks` не null | 1 или 0 |
| `<точка>_x`, `_y`, `_z`, `_vis`, `_pres` | `Landmark.x`, `y`, `z`, `visibility`, `presence` | дробь через точку (в Kotlin писать с `Locale.ROOT`), до 5 знаков после точки; допустима запись вида `3e-05`; при `detected = 0` пустые клетки |

Файл в UTF-8, разделитель запятая, первая строка с названиями колонок.

Сверка:

1. Телефон в режиме отладки пишет такой CSV и запоминает счёт Kotlin-модуля.
2. На компьютере: `python replay_csv.py <файл>`.
3. Счёт `replay_csv.py` равен счёту телефона, и предупреждений нет. Предупреждение бывает, если больше половины кадров такие: линия плеч вертикальная (кадр не повёрнут), плечи ниже запястий (перевёрнут на 180 градусов), левое плечо слева (зеркальный).

## Версии и открытые вопросы

Версия 1.0 от 21 октября 2026.

- [ ] iOS: модуль точек на Swift или на Kotlin, когда импорт Swift-пакетов в KMP выйдет из альфы.
- [ ] Модель lite или full на слабых телефонах: по замерам.
- [ ] CPU или GPU для MediaPipe на каждой платформе: по замерам.
- [ ] Список ошибок техники: после экспериментов аналитика.
- [ ] Режим отладки в приложении: запись CSV и счёта.
- [ ] Ориентация приложения (портрет или альбом): от неё зависят пороги подсказок «слишком далеко» и «слишком близко» (доли ширины кадра). Решить с аналитиком.
- [ ] `WorkoutSummary.durationMs`: от первого до последнего кадра или только время, когда человек в кадре. В Python-эталоне итога тренировки пока нет.

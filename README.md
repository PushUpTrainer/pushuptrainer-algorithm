# Счётчик отжиманий: ML-часть

Python-часть мобильного приложения, которое считает отжимания по фронтальной камере телефона. Здесь мы снимаем 12 точек тела с веб-камеры через MediaPipe Pose Landmarker, пишем их в CSV и на этих CSV подбираем логику счётчика. Готовую логику мобильщики переносят в Kotlin Multiplatform.

## Что внутри

| Файл или папка | Зачем нужен |
| --- | --- |
| `extract_pose.py` | веб-камера: скелет и счётчик на экране, точки в CSV |
| `pushup_logic.py` | 12 точек и их порядок, сигнал, подсказки и счётчик: Python-эталон модуля отжиманий |
| `replay_csv.py` | прогоняет счётчик по готовым CSV без камеры: эксперименты, проверка правок, сверка с телефоном |
| `requirements.txt` | библиотеки с точными версиями |
| `setup.cfg` | настройки flake8 и pycodestyle под наши комментарии |
| `data/labels.csv` | разметка записей: сколько отжиманий было на самом деле |
| `data/experiments.csv` | журнал экспериментов, одна строка на запуск |
| `samples/` | две готовые записи (только координаты точек), чтобы начать без камеры. Они сделаны прошлой версией `extract_pose.py`: в них нет пропусков кадров, а в `.meta.json` надёжно только `reps_counted` |
| `docs/` | документы команды, список в конце |
| `models/` | модели MediaPipe, скачиваются сами, в git не попадают |
| `output/` | CSV с записей, в git не попадают |

## Быстрый старт

Нужен Python 3.13, обязательно 64-битный. Всё проверено на Windows 11 с Python 3.13.15. Команды выполняем в папке проекта (той, где лежит этот README).

**Windows** (PowerShell или терминал PyCharm):

```powershell
py -3.13 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe extract_pose.py
```

Если русский текст в консоли выводится криво, перед запуском выполни `$env:PYTHONUTF8 = "1"`.

**Mac** (Терминал):

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python extract_pose.py
```

Подойдёт только Mac на Apple Silicon (M1 и новее) с macOS 13 или новее: для Mac с Intel у MediaPipe нет готовой сборки, и установка не пройдёт. На Mac установку пока не проверяли.

На Mac при первом запуске система спросит доступ к камере для Терминала (или PyCharm): разреши его в настройках, раздел «Конфиденциальность и безопасность», «Камера».

В PyCharm достаточно выбрать интерпретатор из `.venv` (Settings, Project, Python Interpreter) и запускать скрипты кнопкой Run.

Дальше в примерах `python` значит Python из `.venv`. В терминале PyCharm он уже включён, и `python` работает как есть. В обычном PowerShell вместо `python` пиши `.venv\Scripts\python.exe`, на Mac `.venv/bin/python`.

Проверка без камеры: `python replay_csv.py samples` должен показать две записи и строку «Ошибка счёта: 0.00».

## Как получить точки

```bash
python extract_pose.py                 #веб-камера 0, модель full
python extract_pose.py --input 1       #другая камера, если камер несколько
python extract_pose.py --model lite    #модель lite, full или heavy
```

- Окно закрывается по Esc. На Windows можно и крестиком.
- MediaPipe работает в режиме LIVE\_STREAM, как на телефоне: модель считает в фоне и пропускает кадры, пока занята. В CSV попадают только обработанные кадры, поэтому номера в колонке `frame` идут с пропусками.
- Модель скачивается сама в `models/` при первом запуске с этой моделью.
- Результат каждой записи лежит в `output/csv/<модель>/`: `webcam_<дата>_<время>.csv` с точками и `.meta.json` с итогами (сколько кадров дала камера, сколько обработала модель, скорость и сколько повторов насчитано вживую).
- Видео не сохраняется: в CSV только координаты точек.

## Разметка записей

Чтобы считать ошибку счётчика, для каждой записи нужен настоящий счёт. Его пишем в `data/labels.csv`, по строке на запись. Правь файл в текстовом редакторе (PyCharm или Блокнот), разделитель запятая. Excel лучше не брать: русский Excel сохраняет CSV через точку с запятой, и `replay_csv.py` такую разметку не прочитает (он об этом предупредит).

| Колонка | Что значит |
| --- | --- |
| `video` | имя CSV-файла без `.csv`, например `webcam_20261017_115256` |
| `reps` | сколько отжиманий было на самом деле |
| `view` | ракурс, например `front` или `front_low` |
| `light` | свет, например `good` или `dim` |
| `person` | кто снят: по этой колонке записи делят на настроечные и контрольные |

```csv
video,reps,view,light,person
webcam_20261017_115256,7,front,,p1
webcam_20261017_120154,2,front,,p1
```

Обязательны только `video` и `reps`, остальные клетки можно оставить пустыми. Сейчас в файле размечены две записи из `samples/`.

В `person` пиши условное имя (`p1`, `p2`), а не настоящее: файл лежит в git.

## Прогон счётчика по CSV

```bash
python replay_csv.py                              #все CSV из output/csv/
python replay_csv.py samples                      #готовые записи из репозитория
python replay_csv.py output/csv/lite              #одна папка
python replay_csv.py samples/webcam_20261017_115256.csv  #один файл
```

Пока записей с камеры нет, папки `output/csv` тоже нет, и скрипт без аргументов пишет «CSV не найдены». Скрипт ничего не записывает, только печатает таблицу:

| Колонка | Что значит |
| --- | --- |
| `файл` | имя CSV |
| `кадров` | сколько строк в CSV, то есть сколько кадров обработала модель |
| `секунд` | длительность записи по `time_ms` |
| `человек` | доля кадров, где человек найден (`detected = 1`) |
| `подсказки` | доля кадров, где на экране была бы подсказка |
| `повторы` | сколько насчитал `pushup_logic.py` по этому CSV |
| `вживую` | сколько насчитал счётчик во время записи (из `.meta.json`) |
| `факт` | сколько было на самом деле (из `data/labels.csv`) |

Если хоть одна запись размечена, внизу печатается ошибка счёта (среднее от «насчитано минус на самом деле» по модулю) и доля точных записей. Это главные метрики экспериментов. Остальные метрики из документа [Модули, данные и эксперименты](docs/modules_experiments.md) (задержку, лишние и пропущенные повторы) скрипт пока не считает.

Метрики считаются по тем записям, которые ты дал скрипту. Поэтому контрольные записи держи в отдельной папке, например `output/control/`, и запускай `python replay_csv.py output/control` только один раз, для финального варианта. При подборе параметров запускай скрипт на папке с настроечными записями.

Ещё скрипт предупреждает, если кадр похож на неповёрнутый, перевёрнутый на 180 градусов или зеркальный: это нужно для сверки с телефоном.

Пока `pushup_logic.py` не менялся, `повторы` и `вживую` совпадают. После правки счётчика колонка `вживую` остаётся старой, а `повторы` показывают новый вариант.

## Формат CSV

Одна строка на обработанный кадр, 66 колонок: 6 служебных (`video`, `frame`, `time_ms`, `width`, `height`, `detected`) и по 5 на каждую из 12 точек (`<точка>_x`, `_y`, `_z`, `_vis`, `_pres`). У кадра без человека `detected = 0` и пустые клетки. Ось времени: `time_ms`, а не номер кадра. CSV «сырой»: точки не сглажены и не отброшены, всю очистку делает модуль отжиманий. Подробно в документе [Контракт данных](docs/data_contract.md).

## Как работает базовый счётчик

Всё в `pushup_logic.py`.

1. **Сигнал.** Насколько плечи выше запястий, в ширинах плеч: (средний y запястий минус средний y плеч) делим на расстояние между плечами. Руки прямые: число большое. Грудь у пола: маленькое. Деление на ширину плеч убирает зависимость от расстояния до камеры. Если хоть одно плечо или запястье видно хуже `MIN_VIS`, у кадра нет сигнала и счётчик его пропускает.
2. **Сглаживание.** Медиана последних `SMOOTH_WINDOW` значений сигнала: убирает одиночные скачки точек.
3. **«Верх».** Самое большое сглаженное значение за последние `TOP_WINDOW` кадров с сигналом. Случайный скачок вверх забывается, когда выходит из окна. Оба окна считают только кадры с сигналом: кадр без сигнала окно не сдвигает. Поэтому, если человек пропадает из кадра, окно «верха» по времени тянется дольше.
4. **Пороги.** Человек «внизу», когда сигнал ниже `DOWN_LEVEL` от «верха». «Вверху», когда снова выше `UP_LEVEL` от «верха».
5. **Повтор** засчитывается в момент подъёма, если внизу сигнал правда опускался ниже порога `DOWN_LEVEL`.
6. **Подсказки** (по важности, показываем первую): «Встаньте в кадр» (человек не найден), «Не видно плеч или рук» (хоть одна из 6 точек рук видна хуже `MIN_VIS`), «Слишком далеко от камеры» и «Слишком близко к камере» (по ширине плеч в долях ширины кадра).

| Константа | Значение | Что делает | Эксперимент |
| --- | --- | --- | --- |
| `MIN_VIS` | 0.5 | порог видимости точки | E1 |
| `SMOOTH_WINDOW` | 5 | сколько значений берём в медиану | E2 |
| `shoulder_height` | функция | формула сигнала | E3 |
| `DOWN_LEVEL` | 0.55 | порог «внизу», доля от «верха» | E4 |
| `UP_LEVEL` | 0.85 | порог «вверху», доля от «верха» | E4 |
| `TOP_WINDOW` | 150 кадров с сигналом | окно поиска «верха» | E5 |
| `--model` в `extract_pose.py` | full | модель MediaPipe | E6 |
| `TOO_FAR_WIDTH` | 0.12 | ширина плеч, уже которой «слишком далеко» | E7 |
| `TOO_CLOSE_WIDTH` | 0.7 | ширина плеч, шире которой «слишком близко» | E7 |

Окна `SMOOTH_WINDOW` и `TOP_WINDOW` пока в кадрах. В режиме LIVE\_STREAM кадры идут неравномерно, поэтому их нужно перевести в миллисекунды. Это сделает ML-инженер, пункт есть в списке «Что дальше» документа [Модули, данные и эксперименты](docs/modules_experiments.md).

## Что дальше аналитику

1. Пройти быстрый старт, запустить `python replay_csv.py samples` и сделать пробную запись.
2. Набрать записи: их делаем сами с веб-камеры (себя и знакомых), CSV передаём друг другу в чате команды. Каждую запись разметить в `data/labels.csv`. Видео нигде не сохраняется, в CSV только координаты точек.
3. Провести эксперименты по документу [Модули, данные и эксперименты](docs/modules_experiments.md) и записывать каждый запуск в `data/experiments.csv` (колонки описаны там же). Метрики считает `replay_csv.py`. На текущем коде уже можно делать E2 (медиана и экспоненциальное сглаживание), E3, E4 и E7. Для E1 и E5 нужны окна в миллисекундах и шаги очистки 2 и 3: их добавит ML-инженер.
4. Когда версия финальная, сказать мобильщикам и переслать им [памятку](docs/mobile_handoff.md) и [контракт](docs/data_contract.md).

## Правила оформления

В текстах нет тире, а в комментариях нет пробела после решётки (`#так`). PyCharm подсвечивает такие комментарии (коды E262 и E265). Как убрать подсветку: Settings, Editor, Inspections, Python, PEP 8 coding style violation, в списке Ignore errors добавить E262 и E265.
